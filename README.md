# HA Migration

A data migration utility designed to ingest data from CSV files and transform each row into itemized OpenMRS entities 
formatted for OpenMRS DB Sync. Messages are published to an Apache ActiveMQ Artemis queue for consumption by the OpenMRS 
DB Sync Receiver. See [OpenMRS DB sync](https://github.com/mekomsolutions/openmrs-dbsync) project.

---

## Architecture Overview

The migration pipeline operates through a modular ingestion and itemization lifecycle:

1. **CSV Ingestion & Deserialization**:
   The `Processor` uses `CsvParser` (powered by Jackson CSV) to stream rows from a specified CSV file and map each row 
   into a **Root Data Model** object (e.g., `PatientData`, `VisitData`).
2. **Itemization (`BaseRowItemizer`)**:
   A root record represents the top-level entity in the CSV file and encapsulates data spanning multiple related OpenMRS 
   database entities (for example, a Visit containing multiple Encounters, where each Encounter contains multiple 
   Observations). A dedicated Spring component extending `BaseRowItemizer<T>` decomposes each root object into a list of 
   `BaseEntity` instances, establishing deterministic UUIDs and relational links.
3. **OpenMRS DB Sync Transformation & Transmission**:
   Each itemized `BaseEntity` is wrapped inside a `SyncModel` which matches that from the OpenMRS DB sync, each entity 
   maps it to its corresponding OpenMRS DB Sync model class name (e.g., `org.openmrs.eip.dbsync.model.PatientModel`, 
   `org.openmrs.eip.dbsync.model.PatientIdentifierModel`).
4. **Queue Publishing & Resume Tracking**:
   Batches of JSON messages are published to ArtemisMQ. The migration offset is saved in a `<entity_type>-offset.json` 
   file after each batch to support seamless resume capabilities.

---

> [!IMPORTANT]
When the application starts ingesting a file, it can't be edited until the entire file is processed.

## How to update the code to ingest a file containing other Entity Types (Developer Guide)

To extend the application to ingest and itemize a file containing a new Root entity type (for example, Visits containing 
multiple Encounters and Observations), follow the step-by-step guide below.

```
+--------------------+       +-----------------------+       +-------------------------+       +------------------------+
|      CSV File      | ----> |    Root Data Model    | ----> |      BaseRowItemizer    | ----> |   OpenMRS DB Sync      |
|    (e.g., visits)  |       |   (e.g., VisitData)   |       |  (e.g., VisitItemizer)  |       |   JSON -> ArtemisMQ    |
+--------------------+       +-----------------------+       +-------------------------+       +------------------------+
```

---

### Step 1: Create the Root CSV Data Model

Create a POJO under `net.mekomsolutions.ha.migration.data` representing a single root record (row) in the CSV file. Use 
Jackson CSV annotations to map CSV header columns to class fields.

In this example, each CSV row represents an OpenMRS Visit containing triage and clinical consultation encounters along 
with their corresponding observations:

```java
public class VisitData {

    @Getter
    @Setter
    @JsonProperty("patient_id")
    private String patientId;

    @Getter
    @Setter
    @JsonProperty("consultation_date")
    private String encounterDatetime;

    @Getter
    @Setter
    @JsonProperty("systolic")
    private Double systolic;

    @Getter
    @Setter
    @JsonProperty("diastolic")
    private Double diastolic;

    @Getter
    @Setter
    @JsonProperty("temperature")
    private Double temperature;

    @Getter
    @Setter
    @JsonProperty("diagnosis")
    private String diagnosis;
}
```

### Step 2: Define OpenMRS Entity Models (`model` package)

Ensure all OpenMRS target entities generated by itemization are defined in `net.mekomsolutions.ha.migration.model` extending `BaseEntity`.

In OpenMRS, a Visit links to a Patient; an Encounter links to both a Patient and a Visit; and an Observation (Obs) links to a Patient (Person), an Encounter, and optionally a Concept.

#### Visit Entity
```java
public class Visit extends BaseEntity {

    @Getter
    @Setter
    private String patientUuid;

    @Getter
    @Setter
    private String visitTypeUuid;

    @Getter
    @Setter
    private String locationUuid;

    @Getter
    @Setter
    private LocalDateTime startDatetime;

    @Getter
    @Setter
    private LocalDateTime stopDatetime;

    @Getter
    @Setter
    private boolean voided = false;

    @Override
    public String getUuidTextPrefix() {
        return "visit_";
    }
}
```

#### Encounter Entity
```java
public class Encounter extends BaseEntity {

    @Getter
    @Setter
    private String encounterTypeUuid;

    @Getter
    @Setter
    private String patientUuid;

    @Getter
    @Setter
    private String visitUuid;

    @Getter
    @Setter
    private String locationUuid;

    @Getter
    @Setter
    private LocalDateTime encounterDatetime;

    @Getter
    @Setter
    private boolean voided = false;

    @Override
    public String getUuidTextPrefix() {
        return "encounter_";
    }
}
```

#### Observation (Obs) Entity
```java
public class Obs extends BaseEntity {

    @Getter
    @Setter
    private String personUuid;

    @Getter
    @Setter
    private String encounterUuid;

    @Getter
    @Setter
    private String conceptUuid;

    @Getter
    @Setter
    private LocalDateTime obsDatetime;

    @Getter
    @Setter
    private Double valueNumeric;

    @Getter
    @Setter
    private String valueText;

    @Getter
    @Setter
    private String valueCodedUuid;

    @Getter
    @Setter
    private boolean voided = false;

    @Override
    public String getUuidTextPrefix() {
        return "obs_";
    }
}
```

*Key BaseEntity conventions:*
- `uuid`: Primary UUID of the OpenMRS record.
- `creatorUuid`: Light reference string formatted as `org.openmrs.eip.dbsync.entity.light.UserLight(<UUID>)`.
- `dateCreated`: Creation timestamp (`LocalDateTime`).
- Related entity references must use light reference notation, e.g.:
  `org.openmrs.eip.dbsync.entity.light.PatientLight(<PATIENT_UUID>)`,
  `org.openmrs.eip.dbsync.entity.light.VisitLight(<VISIT_UUID>)`,
  `org.openmrs.eip.dbsync.entity.light.EncounterLight(<ENCOUNTER_UUID>)`.

### Step 3: Register DB Sync Class Mappings

1. Add the sync model and light entity class names in `net.mekomsolutions.ha.migration.Constants`:

```java
public final static String SYNC_CLASS_VISIT = SYNC_PKG + "model.VisitModel";
public final static String SYNC_CLASS_ENCOUNTER = SYNC_PKG + "model.EncounterModel";
public final static String SYNC_CLASS_OBS = SYNC_PKG + "model.ObservationModel";

public final static String SYNC_CLASS_VISIT_LIGHT = SYNC_PKG + "entity.light.VisitLight";
public final static String SYNC_CLASS_ENCOUNTER_LIGHT = SYNC_PKG + "entity.light.EncounterLight";
public final static String SYNC_CLASS_VISIT_TYPE_LIGHT = SYNC_PKG + "entity.light.VisitTypeLight";
public final static String SYNC_CLASS_ENCOUNTER_TYPE_LIGHT = SYNC_PKG + "entity.light.EncounterTypeLight";
public final static String SYNC_CLASS_CONCEPT_LIGHT = SYNC_PKG + "entity.light.ConceptLight";
```

2. Register the mapping between your `BaseEntity` classes and their sync model class names in `net.mekomsolutions.ha.migration.MessageUtils`:

```java
private static final Map<Class<? extends BaseEntity>, String> TYPE_TO_SYNC_CLASS_MAP = Map.of(
    Patient.class, Constants.SYNC_CLASS_PATIENT,
    PatientIdentifier.class, Constants.SYNC_CLASS_ID,
    PersonAddress.class, Constants.SYNC_CLASS_ADDRESS,
    PersonAttribute.class, Constants.SYNC_CLASS_ATTRIBUTE,
    PersonName.class, Constants.SYNC_CLASS_NAME,
    Visit.class, Constants.SYNC_CLASS_VISIT,
    Encounter.class, Constants.SYNC_CLASS_ENCOUNTER,
    Obs.class, Constants.SYNC_CLASS_OBS
);
```

### Step 4: Implement the Itemizer (`BaseRowItemizer<T>`)

Create a Spring `@Component` class extending `BaseRowItemizer<YourDataClass>` in `net.mekomsolutions.ha.migration.itemizer`.

Implement `itemize(YourDataClass data)` to decompose the root object into individual OpenMRS entities (Visit -> Encounters -> Observations).

```java
@Component
public class VisitItemizer extends BaseRowItemizer<VisitData> {

    @Override
    public List<BaseEntity> itemize(VisitData data) {
        final String creator = Constants.SYNC_CLASS_USER_LIGHT + "(" + Constants.DAEMON_USER_UUID + ")";
        final String patUuid = UUID.nameUUIDFromBytes(data.getPatientIdentifier().getBytes(UTF_8)).toString();
        final String patientLight = Constants.SYNC_CLASS_PATIENT_LIGHT + "(" + patUuid + ")";
        final String personLight = Constants.SYNC_CLASS_PERSON_LIGHT + "(" + patUuid + ")";

        List<BaseEntity> entities = new ArrayList<>();

        // 1. Root Entity: Create Visit
        String visitUuid = UUID.nameUUIDFromBytes(("visit-" + data.getVisitId()).getBytes(UTF_8)).toString();
        String visitLight = Constants.SYNC_CLASS_VISIT_LIGHT + "(" + visitUuid + ")";

        Visit visit = new Visit();
        visit.setUuid(visitUuid);
        visit.setPatientUuid(patientLight);
        visit.setVisitTypeUuid(Constants.SYNC_CLASS_VISIT_TYPE_LIGHT + "(" + Constants.VISIT_TYPE_UUID + ")");
        visit.setStartDatetime(LocalDateTime.parse(data.getVisitStartDate()));
        if (data.getVisitStopDate() != null) {
            visit.setStopDatetime(LocalDateTime.parse(data.getVisitStopDate()));
        }
        visit.setCreatorUuid(creator);
        visit.setDateCreated(Processor.date);
        entities.add(visit);

        // 2. First Child Encounter: Triage Encounter

        // 3. Second Child Encounter: Clinical Consultation Encounter

        return entities;
    }
}
```

### Step 5: Register the Enum in `EntityType`

Add the new Root entity type to `net.mekomsolutions.ha.migration.EntityType` with its target class and estimated/maximum item count per row (used to pre-size batch collections):

```java
public enum EntityType {

    PATIENT(PatientData.class, 16),
    VISIT(VisitData.class, 12);

    @Getter
    private Class<?> clazz;

    @Getter
    private int itemCountPerRow;

    EntityType(Class<?> clazz, int itemCountPerRow) {
        this.clazz = clazz;
        this.itemCountPerRow = itemCountPerRow;
    }
}
```

## Running the Migration

Run the application using Spring Boot with the target `--type` and `--file` command-line arguments:

```bash
java -jar target/ha-migration-*.jar -type=VISIT --file=visits.csv
```

### Key Configuration Parameters

| Property / Argument | Description | Default / Example |
| :--- | :--- | :--- |
| `--type` | The Root `EntityType` enum name | `PATIENT`, `VISIT` |
| `--file` | CSV file name located in `data.file.directory` | `visits.csv` |
| `data.file.directory` | Directory containing source CSV files | `/path/to/csv/files` |
| `batch.size` | Number of CSV rows processed per transacted JMS batch | `50` |
| `sync.source.id` | Unique identifier of this migration sender node | `migration-node-1` |
| `sync.queue.name` | ActiveMQ Artemis queue name for DB sync | `openmrs.sync` |
| `spring.artemis.broker-url` | ActiveMQ Artemis connection URL | `tcp://localhost:61616` |
